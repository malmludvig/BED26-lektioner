Merge conflicts

När två branches har ändrat samma rad – så läser du konflikten, löser den eller ångrar dig.

Merge-konflikt

Båda branches har ändrat samma rad. Git kan inte välja åt dig:

git merge meny
CONFLICT (content): Merge conflict in Program.cs
<<<<<<< HEAD
Console.WriteLine("Välkommen!");
=======
Console.WriteLine("Välkommen till Kaffekoppen!");
>>>>>>> meny

Läs konflikten

Git skriver in båda versionerna i filen och märker ut dem:

<<<<<<< HEADStart på konflikten
Console.WriteLine("Välkommen!");Din version – branchen du står på (main)
=======Skiljelinje
Console.WriteLine("Välkommen till Kaffekoppen!");Den andra versionen – från meny
>>>>>>> menySlut på konflikten

Du bestämmer vad som ska stå kvar. Tre vanliga val:

Behåll din

Console.WriteLine("Välkommen!");

Behåll den andra

Console.WriteLine("Välkommen till Kaffekoppen!");

Behåll båda

Console.WriteLine("Välkommen!");
Console.WriteLine("Välkommen till Kaffekoppen!");

De grå raderna – <<<<<<<, ======= och >>>>>>> – ska alltid bort. Annars bygger inte programmet.

Lös konflikten

  1. Öppna filen. HEAD = din branch, nederst = den andra.
  2. Skriv det som ska stå kvar. Ta bort <<<<<<<, =======, >>>>>>>.
  3. Bygg och testa.
git add Program.cs
git commit -m "Slå ihop meny"

Konflikter är normala – inte ett fel. Små, täta merges ger små konflikter.

Ångra dig: git merge --abort

Blev det en konflikt du inte vill lösa just nu? Du kan alltid backa.

git merge --abort     # ångra – tillbaka till innan merge
Innan git mergeallt fungerar
→
Konfliktfiler fulla av <<< === >>>
→
git merge --aborttillbaka till start
  • Filerna blir exakt som de var innan du skrev git merge.
  • Inget försvinner – branchen meny och alla dess commits finns kvar.
  • Du kan försöka merga igen senare, när du är redo.

Fungerar medan mergen pågår – alltså innan du har gjort git commit. Osäker? Kör git status: står det "You have unmerged paths" pågår en merge.
