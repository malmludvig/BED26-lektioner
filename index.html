1. Varför Git?

Git är ett program för versionshantering. Det sparar ögonblicksbilder av ditt projekt så att du alltid kan gå tillbaka.

Utan GitMed Git
Kaffekoppen_kopia.zip, Kaffekoppen_FUNKAR.zip …En mapp – hela historiken finns inuti
"Vad ändrade jag igår?" – ingen aninggit diff visar exakt vilka rader
Skickar filer fram och tillbaka på mejlAlla jobbar i samma repo på GitHub
Råkar radera något → bortaHämta tillbaka från en tidigare commit

Git är programmet på din dator. GitHub är en webbplats där du kan lägga upp dina Git-repon och dela dem. Man kan använda Git helt utan GitHub.

3. Installera och ställ in Git

Ladda ner Git från git-scm.com (Windows: kör installationen med standardvalen). Öppna sedan en terminal – till exempel Git Bash eller terminalen i Visual Studio (View → Terminal).

git --version
git version 2.47.0.windows.1

Berätta för Git vem du är. Det görs en gång per dator och syns på alla dina commits:

git config --global user.name "Ada Lovelace"
git config --global user.email "ada@exempel.se"
git config --global init.defaultBranch main

Rader som börjar med ett gult kommando skriver du själv. Text efter # är kommentarer. Vanlig vit text är det som terminalen skriver ut.

4. Ditt första repo

Skapa ett projekt och ett repo

mkdir GitDemo
cd GitDemo
dotnet new console      # skapar Program.cs och GitDemo.csproj
dotnet new gitignore    # skapar .gitignore för C#-projekt
git init                # gör mappen till ett Git-repo
Initialized empty Git repository in C:/Users/Ada/GitDemo/.git/

.gitignore – filer Git ska strunta i

När du bygger projektet skapas mapparna bin/ och obj/. De går alltid att bygga om och ska inte sparas i Git. Filen .gitignore listar sådant:

bin/
obj/
.vs/

git status – vad har hänt?

Kör git status ofta. Den berättar vilka filer som är ändrade och vad som ligger i staging.

git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .gitignore
        GitDemo.csproj
        Program.cs

nothing added to commit but untracked files present (use "git add" to track)

git add – välj vad som ska sparas

git add Program.cs     # en fil
git add .              # alla ändrade filer i mappen

git commit – spara en ögonblicksbild

git commit -m "Skapa konsolprojekt"
[main (root-commit) 3f2a1c9] Skapa konsolprojekt
 3 files changed, 512 insertions(+)

Siffrorna 3f2a1c9 är commitens id (en hash). Varje commit får ett unikt id.

Arbetsflödet – om och om igen

  1. Ändra kod i Visual Studio
  2. git status – vad har ändrats?
  3. git add .
  4. git commit -m "Beskriv vad du gjorde"

Bra commit-meddelanden

DåligtBra
fixRätta studentrabatten när summan är över 200 kr
asdfLägg till klassen Pastry med bäst före-datum

Tumregel: meddelandet ska fortsätta meningen "Den här commiten kommer att …". Commita ofta – små commits är lätta att förstå och ångra.

5. Titta i historiken

git log --oneline        # en rad per commit, nyast överst
a81d4e2 Lägg till klassen Drink
7c90b13 Lägg till basklassen Product
3f2a1c9 Skapa konsolprojekt

git diff                 # vad har ändrats sedan senaste commit (ej i staging)
git diff --staged        # vad ligger i staging just nu
git show a81d4e2         # visa en specifik commit

Så här ser git diff ut. Rader med − har tagits bort, rader med + har lagts till:

-    public virtual decimal CalculatePrice() { return 0; }
+    public virtual decimal CalculatePrice() { return basePrice; }

6. Ångra

SituationKommando
Jag har ändrat en fil och vill ha tillbaka hur den såg ut vid senaste commitgit restore Program.cs
Jag la en fil i staging men vill ta bort den därifrån (ändringen finns kvar)git restore --staged Program.cs
Jag skrev fel i senaste commit-meddelandet (inte pushat än)git commit --amend -m "Nytt meddelande"
En gammal commit var fel – skapa en ny commit som tar bort ändringengit revert a81d4e2

Se upp: git restore på en fil slänger dina osparade ändringar för gott. Ändringar som är commitade går däremot nästan alltid att få tillbaka.

7. Branches och merge

En branch är ett eget spår där du kan prova något nytt utan att förstöra main. När det fungerar slår du ihop (merge) det med main.

gitGraph
  commit id: "Skapa projekt"
  commit id: "Product"
  branch studentrabatt
  checkout studentrabatt
  commit id: "IsStudent"
  commit id: "Discount()"
  checkout main
  commit id: "Rätta stavfel"
  merge studentrabatt
  commit id: "Kvitto"

git branch                     # lista branches – * visar var du är
git switch -c studentrabatt    # skapa en ny branch och gå dit
# ... ändra kod, add, commit ...
git switch main                # gå tillbaka till main
git merge studentrabatt        # hämta in ändringarna i main
git branch -d studentrabatt    # ta bort branchen när den är klar

Merge-konflikt

Om två branches har ändrat samma rad kan Git inte välja åt dig. Då blir det en konflikt och Git markerar raden i filen:

<<<<<<< HEAD
            return basePrice + 5;
=======
            return basePrice + 8;
>>>>>>> studentrabatt

Så löser du en konflikt

  1. Öppna filen. Överst (HEAD) är din version, nederst den andra branchens.
  2. Bestäm vad som ska stå kvar och ta bort markeringarna <<<<<<<, ======= och >>>>>>>.
  3. Kontrollera att programmet bygger.
  4. git add . och git commit – klart!

Visual Studio har ett eget verktyg för konflikter: klicka på filen i Git Changes och välj vilken sida du vill behålla.

8. GitHub: dela ditt repo

Skapa ett konto på github.com och ett nytt, tomt repository (bocka inte i README eller .gitignore). GitHub visar då en sida med Quick setup och de kommandon du behöver:

Kommandona från GitHub

…or create a new repository on the command line – du har inget lokalt repo än:

echo "# testtest" >> README.md   # skapa en README-fil
git init                          # gör mappen till ett repo
git add README.md
git commit -m "first commit"
git branch -M main                # döp branchen till main
git remote add origin https://github.com/malmludvig/testtest.git
git push -u origin main           # skicka upp och koppla ihop

…or push an existing repository from the command line – du har redan gjort git init och commits:

git remote add origin https://github.com/malmludvig/testtest.git
git branch -M main
git push -u origin main

Byt malmludvig/testtest mot ditt eget användarnamn och repo. Har du följt avsnitt 4 har du redan ett repo – då är det det andra blocket du ska använda.

För projektet GitDemo från avsnitt 4 blir det alltså:

git remote add origin https://github.com/ditt-namn/GitDemo.git
git push -u origin main      # första gången: -u kopplar ihop main med origin/main
git push                     # sedan räcker det så här
KommandoGör
git clone <url>Laddar ner ett repo från GitHub – med hela historiken
git pushSkickar dina commits upp till GitHub
git pullHämtar ner andras commits från GitHub

Jobba i grupp: börja alltid med git pull innan du börjar koda, och git push när du är klar. Då blir det färre konflikter.

Första gången du pushar frågar Git efter inloggning. På Windows öppnas ett fönster där du loggar in på GitHub i webbläsaren.

10. Övningar

Gör övningarna i en terminal. Försök själv först – öppna facit när du är klar.

Övning 1: Första commiten

  1. Skapa en ny mapp GitOvning med ett konsolprojekt och en .gitignore.
  2. Gör mappen till ett Git-repo.
  3. Kör git status. Varför syns inte bin/ och obj/?
  4. Lägg alla filer i staging och gör en commit med meddelandet "Skapa projekt".
Visa facit 
mkdir GitOvning
cd GitOvning
dotnet new console
dotnet new gitignore
git init
git status
git add .
git commit -m "Skapa projekt"

bin/ och obj/ syns inte eftersom de står i .gitignore. (Om du inte har byggt projektet än finns de inte heller.)

Övning 2: Ändra, titta, spara

  1. Ändra Program.cs så att programmet skriver ut ditt namn.
  2. Kör git status och git diff. Vad visar de?
  3. Commita ändringen med ett bra meddelande.
  4. Gör två ändringar till, med en commit för varje. Visa historiken på en rad per commit.
Visa facit 
git status                # Program.cs står som "modified"
git diff                  # visar raden som togs bort (-) och lades till (+)
git add Program.cs
git commit -m "Skriv ut mitt namn"
# ... två ändringar till ...
git log --oneline
c4e1a90 Fråga efter användarens ålder
9b2f7d3 Skriv ut dagens datum
51aa0e6 Skriv ut mitt namn
2d8c3f1 Skapa projekt

Övning 3: Ångra en ändring

  1. Radera allt innehåll i Program.cs och spara filen. (Ja, verkligen!)
  2. Kör git status.
  3. Få tillbaka filen som den var vid senaste commit.
Visa facit 
git status
        modified:   Program.cs
git restore Program.cs
git status
nothing to commit, working tree clean

Filen är tillbaka eftersom den fanns i en commit. Därför ska man commita ofta!

Övning 4: En branch

  1. Skapa en branch meny och gå till den.
  2. Lägg till en enkel meny i Program.cs och commita.
  3. Gå tillbaka till main. Titta i Program.cs – vart tog menyn vägen?
  4. Merga in meny i main och ta bort branchen.
Visa facit 
git switch -c meny
# ... skriv menyn ...
git add .
git commit -m "Lägg till meny"
git switch main          # menyn är borta – den finns bara på branchen meny
git merge meny           # nu finns menyn i main också
git branch -d meny

Filerna i arbetsmappen byts ut när du byter branch. Inget är borta – det ligger på en annan branch.

Övning 5: Skapa en konflikt (och lös den)

  1. Skapa en branch halsning. Ändra raden med Console.WriteLine till "Hej från branchen!" och commita.
  2. Gå till main. Ändra samma rad till "Hej från main!" och commita.
  3. Merga halsning in i main. Vad händer?
  4. Lös konflikten så att programmet skriver ut båda raderna.
Visa facit 
git switch -c halsning
# ändra raden, sedan:
git commit -am "Hälsning från branchen"
git switch main
# ändra samma rad, sedan:
git commit -am "Hälsning från main"
git merge halsning
CONFLICT (content): Merge conflict in Program.cs

Öppna Program.cs, ta bort markeringarna och behåll båda raderna:

Console.WriteLine("Hej från main!");
Console.WriteLine("Hej från branchen!");
git add Program.cs
git commit -m "Slå ihop hälsningarna"

-am är en genväg för git add + git commit -m på filer som Git redan känner till.

Övning 6: Upp på GitHub

  1. Skapa ett tomt repository på GitHub som heter GitOvning.
  2. Koppla ihop ditt lokala repo med det och pusha.
  3. Ladda om sidan på GitHub – syns dina commits?
  4. Med en kompis: klona varandras repon, gör en ändring, pusha. Hämta sedan kompisens ändring i ditt eget repo.
Visa facit 
git remote add origin https://github.com/ditt-namn/GitOvning.git
git push -u origin main

# Kompisen:
git clone https://github.com/ditt-namn/GitOvning.git
cd GitOvning
# ... ändra ...
git commit -am "Ändring från kompisen"
git push

# Du:
git pull

För att kompisen ska få pusha till ditt repo behöver du bjuda in hen: Settings → Collaborators → Add people på GitHub.

Extra: Lägg upp Kaffekoppen

Öppna ditt Kaffekoppen-projekt från vecka 5 i Visual Studio. Använd Git → Create Git Repository… för att skapa ett repo och lägga upp det på GitHub – helt utan terminalen. Gör sedan en ändring och commita och pusha från fönstret Git Changes.
