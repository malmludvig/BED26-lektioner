Vad behöver en fiende?

  • Tillstånd: namn och hälsa.
  • Beteende: attackera och ta skada.
  • Inkapsling: hälsan ändras bara genom TakeDamage() – och blir aldrig negativ.

Klass och objekt

Goblin är en klass – en ritning. Varje new Goblin() är ett eget objekt.

Goblin first = new Goblin();
Goblin second = new Goblin();

first.TakeDamage(10);

Console.WriteLine(first.Health);    // 20
Console.WriteLine(second.Health);   // 30

Två gobliner – två objekt – var sin hälsa.

Enum – svårighetsgrad

public enum Difficulty
{
    Easy,
    Medium,
    Hard
}
Difficulty difficulty = Difficulty.Hard;

En egen typ med ett fast antal värden.

Varför inte en sträng?

string difficulty = "hard";    // eller "Hard"? "svår"? "hrad"?
  • Med en enum går det inte att skriva ett värde som inte finns.
  • Stavfel blir rött i Visual Studio direkt.
  • Visual Studio föreslår värdena när du skriver Difficulty.

Strängar: felet märks när programmet körs. Enum: felet märks när du skriver.

Abstract class: Enemy

public abstract class Enemy
{
    public string Name { get; }
    public int Health { get; private set; }
    public Difficulty Difficulty { get; }

    protected Enemy(string name, int health, Difficulty difficulty)
    {
        Name = name;
        Health = health;
        Difficulty = difficulty;
    }

    public void TakeDamage(int damage)
    {
        if (damage > 0)
        {
            Health = Math.Max(0, Health - damage);
        }
    }

    public abstract void Attack();
}

Vad betyder det?

  • abstract class – man kan inte skriva new Enemy(...).
  • private set – hälsan kan bara ändras inifrån klassen.
  • Math.Max(0, …) – hälsan blir aldrig mindre än 0.
  • abstract void Attack(); – ingen kropp. Varje fiende måste skriva sin egen.

Allt som är gemensamt ligger i Enemy. Det som skiljer sig lämnas åt subklasserna.

En konkret fiende: Goblin

public class Goblin : Enemy
{
    public Goblin() : base("Goblin", 30, Difficulty.Easy)
    {
    }

    public override void Attack()
    {
        Console.WriteLine("Goblinen attackerar med sin klubba!");
    }
}

: base(...) skickar namn, hälsa och svårighetsgrad till Enemy.

Och en Dragon

public class Dragon : Enemy
{
    public Dragon() : base("Drake", 100, Difficulty.Hard)
    {
    }

    public override void Attack()
    {
        Console.WriteLine("Draken sprutar eld!");
    }
}

Polymorfism

List<Enemy> enemies = new List<Enemy>

Interface: IWeapon

public interface IWeapon
{
    int Use();
}

Ett kontrakt: alla vapen kan användas, och svarar med hur mycket skada de gör.

Sword och Bow

public class Sword : IWeapon
{
    public int Use()
    {
        Console.WriteLine("Du hugger med svärdet!");
        return 10;
    }
}
public class Bow : IWeapon
{
    public int Use()
    {
        Console.WriteLine("Du skjuter en pil!");
        return 8;
    }
}

Arv eller composition?

  • Ett hus är en byggnad → arv (ofylld triangel).
  • Ett hus har ett badrum → composition (fylld romb).

Wikipedia: Composition over inheritance

"In object-oriented programming, composition over inheritance (sometimes composition with forwarding or composite reuse) is a common design pattern that tries to achieve code reuse without requiring inheritance."

På svenska: ett vanligt designmönster för att återanvända kod utan att behöva arv.

en.wikipedia.org/wiki/Composition_over_inheritance

Composition over inheritance

Bygg hellre ihop en klass av mindre delar än att ärva från en annan klass.

  • Arv – "är en". Klassen blir en sorts basklass.
  • Composition – "har en". Klassen har ett objekt som gör en del av jobbet.

Huset i kod

Arv – ett hus är en byggnad

class Building
{
}

class House : Building
{
}

Composition – ett hus har ett badrum

class Bathroom
{
}

class House
{
    private Bathroom bathroom = new Bathroom();
}

Exempel: en bil med en motor

Med arv: en ny bilklass för varje motor.

class PetrolCar : Car { }
class ElectricCar : Car { }
class HybridCar : Car { }   // ... och så vidare

Med composition: bilen har en motor.

class Car
{
    public IEngine Engine { get; set; }

    public void Drive() { Engine.Start(); }
}

Byt motor

interface IEngine { void Start(); }

class PetrolEngine : IEngine
{
    public void Start() { Console.WriteLine("Brum brum!"); }
}

class ElectricEngine : IEngine
{
    public void Start() { Console.WriteLine("Bzzzz..."); }
}
Car car = new Car();
car.Engine = new PetrolEngine();
car.Drive();                        // Brum brum!

car.Engine = new ElectricEngine();  // byt motor
car.Drive();                        // Bzzzz...

Fördelar

  • Flexibelt – delar kan bytas medan programmet körs.
  • Färre klasser – inga PetrolCar, ElectricCar … bara nya motorer.
  • Lätt att bygga ut – en ny motor ändrar inte Car.
  • Återanvändning – samma motor i en bil, en båt eller en gräsklippare.
  • Inga långa arvskedjor – en ändring påverkar bara sin egen del.

Arv är inte fel. "Är en" som aldrig ändras → arv. En del som kan bytas → composition.

Spelaren – ett första försök

Player

Vad händer om spelaren ska byta vapen mitt i spelet?

Problemet med arv här

  • Ett objekt kan inte byta klass – en SwordPlayer förblir en SwordPlayer.
  • Varje nytt vapen kräver en ny spelarklass: WandPlayer, AxePlayer, …

Lösning: spelaren har ett vapen i stället för att vara ett.

Composition: Player har ett IWeapon

public class Player
{
    public IWeapon Weapon { get; set; }

    public Player(IWeapon weapon)
    {
        Weapon = weapon;
    }

    public void Attack(Enemy enemy)
    {
        int damage = Weapon.Use();
        enemy.TakeDamage(damage);
    }
}

Byt vapen

Player player = new Player(new Sword());
Enemy enemy = new Goblin();

player.Attack(enemy);

player.Weapon = new Bow();

player.Attack(enemy);

Console.WriteLine($"Fiendens hälsa: {enemy.Health}");
Du hugger med svärdet!
Du skjuter en pil!
Fiendens hälsa: 12
