1. Repetition: arv och polymorfism

Arv = en klass bygger vidare på en annan. Läs det som "är en": en Hund är ett Djur.

virtual i basklassen betyder "får skrivas om". override i subklassen skriver om den.

class Animal
{
    protected string name;
    public Animal(string name) { this.name = name; }

    public virtual string Sound() { return "..."; }
}

class Dog : Animal
{
    public Dog(string name) : base(name) { }
    public override string Sound() { return "Voff!"; }
}

class Cat : Animal
{
    public Cat(string name) : base(name) { }
    public override string Sound() { return "Mjau!"; }
}

Polymorfism = samma anrop, olika beteende. Loopen vet inte vilket djur det är – varje objekt svarar själv.

List<Animal> animals = new List<Animal> { new Dog("Fido"), new Cat("Misse") };

foreach (Animal d in animals)
{
    Console.WriteLine(d.Sound());   // Voff!  Mjau!
}

I UML ritas arv med en heldragen linje och ofylld triangel mot basklassen:

classDiagram
  class Animal {
    #name: string
    +Sound() string
  }
  class Dog { +Sound() string }
  class Cat { +Sound() string }
  Animal <|-- Dog
  Animal <|-- Cat

2. Interface

Ett interface är ett kontrakt: en lista över vad en klass kan göra, utan att säga hur. Läs det som "kan": en Bil kan köras.

interface IVehicle
{
    string Name { get; }
    void Drive();              // ingen kropp – bara löftet
}

Klasser som implementerar interfacet måste skriva alla metoder:

class Car : IVehicle
{
    public string Name { get; } = "Bil";
    public void Drive() { Console.WriteLine("Brum brum"); }
}

class Bicycle : IVehicle
{
    public string Name { get; } = "Cykel";
    public void Drive() { Console.WriteLine("Trampar..."); }
}

Flera implementationer = polymorfism igen

List<IVehicle> vehicles = new List<IVehicle> { new Car(), new Bicycle() };

foreach (IVehicle f in vehicles)
{
    f.Drive();
}

En klass kan ha flera interface

Man kan bara ärva från en klass, men implementera hur många interface som helst.

interface IFlying { void Fly(); }

class FlyingCar : IVehicle, IFlying
{
    public string Name { get; } = "Flygbil";
    public void Drive()  { Console.WriteLine("Kör på vägen"); }
    public void Fly() { Console.WriteLine("Lyfter!"); }
}

I UML markeras interfacet med «interface» och implementation ritas med streckad linje och ofylld triangel:

classDiagram
  class IVehicle {
    <<interface>>
    +Name: string
    +Drive()
  }
  class IFlying {
    <<interface>>
    +Fly()
  }
  IVehicle <|.. Car
  IVehicle <|.. Bicycle
  IVehicle <|.. FlyingCar
  IFlying <|.. FlyingCar

Basklass eller interface?

Basklass (arv)Interface

Tumregel: delar klasserna kod → basklass. Delar de bara förmåga → interface.

Övning: Skapa ett objekt

Använd IVehicle och Car från exemplet ovan.

  1. Skapa ett objekt av Car och spara det i en variabel av typen IVehicle.
  2. Skriv ut fordonets namn.
  3. Anropa Drive().
Visa facit 
IVehicle vehicle = new Car();

Console.WriteLine(vehicle.Name);
vehicle.Drive();

Utskrift:

Bil
Brum brum

Variabeln är av typen IVehicle, men objektet är en Car. Man kan aldrig skriva new IVehicle() – ett interface är bara ett kontrakt.
