1. Varför LINQ?

LINQ (Language Integrated Query) är en samling metoder för att ställa frågor till listor. Uppgift: plocka ut alla tal större än 5.

Med en loop

List<int> numbers = new List<int> { 5, 12, 3, 8, 20, 1 };
List<int> bigNumbers = new List<int>();

foreach (int x in numbers)
{
    if (x > 5)
    {
        bigNumbers.Add(x);
    }
}

Med LINQ

List<int> bigNumbers = numbers.Where(x => x > 5).ToList();   // 12, 8, 20

Samma resultat. Loopen beskriver hur datorn ska göra, LINQ beskriver vad du vill ha.

LINQ finns i using System.Linq;. I nya konsolprojekt (.NET 6 och senare) är den redan inkluderad – du behöver inte skriva något.

2. Lambda-uttryck

Det som står inuti Where( … ) är ett lambda-uttryck: en liten metod utan namn.

x => x > 5
// ^      ^
// |      vad som ska räknas ut (här: true eller false)
// parametern – ett element i listan i taget

Läs pilen => som "går till": "x går till x större än 5". Det är samma sak som att skriva en vanlig metod:

static bool IsLarge(int x)
{
    return x > 5;
}

numbers.Where(IsLarge);         // fungerar också
numbers.Where(x => x > 5);     // men lambdan är kortare

Namnet på parametern väljer du själv. Här använder vi x för tal, och en bokstav som påminner om innehållet för objekt: p för produkt, n för namn.

3. De vanligaste metoderna

Alla exempel använder samma lista:

List<int> numbers = new List<int> { 5, 12, 3, 8, 20, 1 };

Filtrera och omvandla

numbers.Where(x => x > 5)          // 12, 8, 20        – behåll de som stämmer
numbers.Select(x => x * 2)         // 10, 24, 6, 16, 40, 2  – gör om varje element
numbers.OrderBy(x => x)            // 1, 3, 5, 8, 12, 20    – sortera stigande
numbers.OrderByDescending(x => x)  // 20, 12, 8, 5, 3, 1    – sortera fallande

Fem enkla Where

Where behåller bara de element där villkoret är true. Elementen ändras inte – du får färre (eller lika många) tillbaka.

numbers.Where(x => x < 5)                // 3, 1                – mindre än 5
numbers.Where(x => x == 8)               // 8                   – exakt 8
numbers.Where(x => x % 2 == 0)           // 12, 8, 20           – jämna tal
numbers.Where(x => x != 3)               // 5, 12, 8, 20, 1     – allt utom 3
numbers.Where(x => x >= 5 && x <= 12)   // 5, 12, 8            – mellan 5 och 12

Fem enkla Select

Select gör om varje element. Du får alltid lika många tillbaka som du skickade in – 6 in, 6 ut.

numbers.Select(x => x + 1)        // 6, 13, 4, 9, 21, 2         – lägg till 1
numbers.Select(x => x * 10)       // 50, 120, 30, 80, 200, 10   – gånger 10
numbers.Select(x => x * x)        // 25, 144, 9, 64, 400, 1     – i kvadrat
numbers.Select(x => "Tal " + x)   // "Tal 5", "Tal 12", …       – gör om till text
numbers.Select(x => x > 5)        // false, true, false, true, true, false

Lägg märke till den sista: Select(x => x > 5) filtrerar inte. Den svarar true eller false för varje tal. Vill du behålla bara de stora talen behöver du Where.

SelectWhere
GörGör om varje elementVäljer ut element
Antal utAlltid lika mångaFärre eller lika många
Lambdan gerDet nya värdettrue eller false

Hämta ett element

numbers.First()                      // 5   – det första
numbers.First(x => x > 10)           // 12  – det första som stämmer
numbers.FirstOrDefault(x => x > 100) // 0   – inget stämmer → standardvärdet
numbers.First(x => x > 100)          // KRASCHAR – inget element hittades

Är du inte säker på att något hittas: använd FirstOrDefault. För tal blir standardvärdet 0, för objekt blir det null.

Ja/nej-frågor

numbers.Any(x => x > 15)    // true  – finns det något?
numbers.All(x => x > 0)     // true  – stämmer det för alla?
numbers.Contains(8)         // true  – finns just 8?

Räkna

numbers.Count()              // 6
numbers.Count(x => x > 5)    // 3
numbers.Sum()                // 49
numbers.Min()                // 1
numbers.Max()                // 20
numbers.Average()            // 8,1666…

Från fråga till lista

Where, Select och OrderBy ger inte en List tillbaka, utan en IEnumerable<T> – "något man kan loopa igenom". Vill du ha en riktig lista: lägg till .ToList().

IEnumerable<int> query = numbers.Where(x => x > 5);
List<int>        list = numbers.Where(x => x > 5).ToList();

var bigNumbers = numbers.Where(x => x > 5).ToList();   // var – kompilatorn räknar ut typen

Koppling till generics och interface

IEnumerable<T> är ett generiskt interface. List<T>, arrayer och många andra samlingar implementerar det – därför fungerar LINQ på alla. Precis som Garage<T> på sidan Generics kunde anropa Drive() på allt som var IVehicle.

3.5 Samma sak med en lista av personer

Samma fem Where och fem Select – men nu är varje element ett Person-objekt i stället för ett tal.

class Person
{
    public string Name { get; }
    public int Age { get; }
    public int ClassId { get; }
    public string City { get; }

    public Person(string name, int age, int classId, string city)
    {
        Name = name;
        Age = age;
        ClassId = classId;
        City = city;
    }
}

List<Person> people = new List<Person>
{
    new Person("Ada", 17, 1, "Stockholm"),
    new Person("Linus", 19, 2, "Göteborg"),
    new Person("Grace", 16, 1, "Malmö"),
    new Person("Bjarne", 18, 2, "Stockholm"),
    new Person("Ola", 20, 1, "Göteborg"),
    new Person("Margaret", 17, 2, "Uppsala")
};

Nu är p en hel person. Med punkt kommer du åt egenskaperna: p.Name, p.Age, p.ClassId, p.City.

Fem enkla Where

Du får tillbaka hela personer – bara färre. Kommentaren visar namnen på de som blir kvar.

people.Where(p => p.Age < 18)                     // Ada, Grace, Margaret        – yngre än 18
people.Where(p => p.City == "Stockholm")          // Ada, Bjarne                 – bor i Stockholm
people.Where(p => p.ClassId == 2)                 // Linus, Bjarne, Margaret     – går i klass 2
people.Where(p => p.City != "Göteborg")           // Ada, Grace, Bjarne, Margaret – alla utom Göteborg
people.Where(p => p.Age >= 17 && p.Age <= 18)     // Ada, Bjarne, Margaret       – mellan 17 och 18

Fem enkla Select

Du får tillbaka lika många – 6 personer in, 6 värden ut. Men det som kommer ut är inte längre personer.

people.Select(p => p.Name)                   // "Ada", "Linus", "Grace", …    – bara namnen
people.Select(p => p.Age + 1)                // 18, 20, 17, 19, 21, 18        – åldern nästa år
people.Select(p => p.City.ToUpper())         // "STOCKHOLM", "GÖTEBORG", …    – stad med versaler
people.Select(p => $"{p.Name} ({p.Age})")    // "Ada (17)", "Linus (19)", …   – gör om till text
people.Select(p => p.Age >= 18)              // false, true, false, true, true, false – myndig?

Where ger tillbaka Person-objekt. Select(p => p.Name) ger tillbaka string och Select(p => p.Age + 1) ger int. Select kan byta typ – Where kan inte.

Tillsammans

Vilka bor i Stockholm? Skriv ut namnen:

List<string> names = people
    .Where(p => p.City == "Stockholm")   // först: välj personer
    .Select(p => p.Name)                 // sedan: ta bara namnet
    .ToList();

Console.WriteLine(string.Join(", ", names));   // Ada, Bjarne

4. LINQ på egna objekt

LINQ blir riktigt användbart när listan innehåller objekt. Vi använder Kaffekoppens meny, med publika egenskaper så att vi kan läsa dem utifrån.

class Product
{
    public string Name { get; }
    public decimal Price { get; }
    public string Category { get; }

    public Product(string name, decimal price, string category)
    {
        Name = name;
        Price = price;
        Category = category;
    }
}

List<Product> menu = new List<Product>
{
    new Product("Kaffe", 30, "Dryck"),
    new Product("Te", 25, "Dryck"),
    new Product("Ostsmörgås", 55, "Smörgås"),
    new Product("Skinksmörgås", 60, "Smörgås"),
    new Product("Kanelbulle", 35, "Bakverk"),
    new Product("Croissant", 30, "Bakverk")
};

Nu är p en hel produkt. Med punkt kommer vi åt dess egenskaper:

var cheap   = menu.Where(p => p.Price < 40);       // Kaffe, Te, Kanelbulle, Croissant
var drinks   = menu.Where(p => p.Category == "Dryck"); // Kaffe, Te
var names      = menu.Select(p => p.Name);           // bara namnen, som string
var sorted = menu.OrderBy(p => p.Price);          // Te först, Skinksmörgås sist

decimal sum   = menu.Sum(p => p.Price);            // 235
decimal mostExpensive  = menu.Max(p => p.Price);            // 60
Product? coffee  = menu.FirstOrDefault(p => p.Name == "Kaffe");

Lägg märke till Select: in går en Product, ut kommer en string. Select kan alltså byta typ.

5. Kedja ihop

Varje LINQ-metod ger tillbaka något nytt som man kan fortsätta på. Läs kedjan uppifrån och ned:

List<string> cheapNames = menu
    .Where(p => p.Price < 40)     // 1. behåll produkter under 40 kr
    .OrderBy(p => p.Price)        // 2. sortera på pris
    .Select(p => p.Name)         // 3. ta bara namnet
    .ToList();                   // 4. gör en lista

Console.WriteLine(string.Join(", ", cheapNames));

6. Gruppera med GroupBy

GroupBy delar upp listan i grupper. Varje grupp har en Key (det man grupperade på) och går själv att använda LINQ på.

foreach (var categoryGroup in menu.GroupBy(p => p.Category))
{
    Console.WriteLine($"{categoryGroup.Key}: {categoryGroup.Count()} st, {categoryGroup.Sum(p => p.Price)} kr");
}

Utskrift:

Dryck: 2 st, 55 kr
Smörgås: 2 st, 115 kr
Bakverk: 2 st, 65 kr

7. Fler användbara metoder

Ta och hoppa över: Take och Skip

numbers.Take(3)              // 5, 12, 3   – de tre första
numbers.Skip(3)              // 8, 20, 1   – allt utom de tre första
numbers.Skip(2).Take(2)      // 3, 8       – hoppa över 2, ta 2
numbers.Last()               // 1          – det sista
numbers.Last(x => x > 5)     // 20         – det sista som stämmer

Tillsammans med sortering blir det en topplista:

numbers.OrderByDescending(x => x).Take(3)   // 20, 12, 8 – de tre största

Skip + Take används för sidor, till exempel i en webbshop: sida 2 med 10 varor per sida är Skip(10).Take(10).

Ta bort dubbletter: Distinct

List<int> dice = new List<int> { 3, 6, 3, 1, 6, 6 };
dice.Distinct()                              // 3, 6, 1

menu.Select(p => p.Category).Distinct()      // Dryck, Smörgås, Bakverk

Sortera på två saker: ThenBy

Kaffe och Croissant kostar båda 30 kr. Vilken kommer först? Med ThenBy bestämmer du vad som avgör när det blir lika.

menu.OrderBy(p => p.Price)      // 1. sortera på pris
    .ThenBy(p => p.Name)        // 2. samma pris? sortera på namn
// Te, Croissant, Kaffe, Kanelbulle, Ostsmörgås, Skinksmörgås

Skriv inte OrderBy(…).OrderBy(…). Då gör den andra sorteringen om ordningen och den första tappar sin betydelse. Använd ThenBy eller ThenByDescending.

Hela objektet med högst värde: MaxBy och MinBy

decimal highest = menu.Max(p => p.Price);             // 60            – bara priset
Product? mostExpensive = menu.MaxBy(p => p.Price);    // Skinksmörgås  – hela produkten
Product? cheapest = menu.MinBy(p => p.Price);         // Te

Max svarar med ett värde. MaxBy svarar med objektet som har det högsta värdet. Det är samma sak som OrderByDescending(p => p.Price).First(), fast kortare.

Slå upp med namn: ToDictionary

Dictionary<string, decimal> prices = menu.ToDictionary(p => p.Name, p => p.Price);

Console.WriteLine(prices["Kaffe"]);   // 30

Första lambdan blir nyckeln, andra blir värdet. Nycklarna måste vara unika – två produkter med samma namn kraschar programmet.

Skapa tal: Enumerable.Range

Enumerable.Range(1, 10)                           // 1, 2, 3 … 10
Enumerable.Range(1, 10).Where(x => x % 2 == 0)    // 2, 4, 6, 8, 10
Enumerable.Range(1, 5).Select(x => x * x)         // 1, 4, 9, 16, 25

Första talet är start, andra är hur många – inte det sista talet. Range(5, 3) ger 5, 6, 7.

8. Jämför två listor

Vilka elever läser både programmering och matte? LINQ kan jämföra två listor.

List<string> programming = new List<string> { "Ada", "Linus", "Grace" };
List<string> math        = new List<string> { "Grace", "Ola", "Ada" };

programming.Concat(math)      // Ada, Linus, Grace, Grace, Ola, Ada
programming.Union(math)       // Ada, Linus, Grace, Ola
programming.Intersect(math)   // Ada, Grace
programming.Except(math)      // Linus

9. Två sätt att skriva: metod- och query-syntax

LINQ kan också skrivas så att det liknar databasspråket SQL. Resultatet blir exakt detsamma.

// Metodsyntax
var a = menu.Where(p => p.Price < 40)
            .OrderBy(p => p.Price)
            .Select(p => p.Name);

// Query-syntax
var b = from p in menu
        where p.Price < 40
        orderby p.Price
        select p.Name;

Tumregel: lär dig metodsyntaxen först. Känn igen query-syntaxen när du ser den.

10. Se upp: frågan körs först när du använder den

Where gör ingenting direkt – den sparar bara frågan. Listan läses först när du loopar, räknar eller gör ToList().

List<int> numbers = new List<int> { 1, 2, 3 };

var query = numbers.Where(x => x > 1);            // ingenting händer än
var list = numbers.Where(x => x > 1).ToList();   // körs nu: 2, 3

numbers.Add(10);

Console.WriteLine(query.Count());   // 3 – listan lästes först nu, 10 kom med
Console.WriteLine(list.Count);     // 2 – en kopia från innan

Vill du ha resultatet som det ser ut just nu: avsluta med .ToList().
