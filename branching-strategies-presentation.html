Git branching strategies

Hur jobbar vi med branches i en grupp – utan att trampa på varandra?

Vad är en branchstrategi?

En överenskommelse i gruppen om hur ni använder branches:

  • Vilka branches finns?
  • Vad ska de heta?
  • Hur kommer koden in i main?

Det viktiga är inte vilken strategi ni väljer – utan att alla gör likadant.

Vi använder feature branch workflow.

Feature branch workflow

main fungerar alltid. Allt nytt görs på en egen feature branch.

gitGraph
  commit id: "Start"
  branch feature/meny
  commit id: "Meny"
  commit id: "Meny klar"
  checkout main
  merge feature/meny
  branch feature/kvitto
  commit id: "Kvitto"
  checkout main
  merge feature/kvitto

En branch per uppgift → klar → in i main → nästa uppgift.

Namnge med feature/

Alla feature branches börjar med feature/ följt av vad den gör:

feature/meny
feature/kvitto
feature/studentrabatt
  • Alla ser direkt att det är en ny funktion.
  • Små bokstäver, inga mellanslag, inga å/ä/ö.
  • / är bara en del av namnet – det grupperar branches i Visual Studio och på GitHub.

Vad är en Pull Request?

En Pull Request (PR) är en fråga du ställer på GitHub:

"Får jag merga min branch in i main?"

Precis som att lämna in ett utkast till läraren innan det blir det riktiga arbetet – någon tittar först, sedan godkänns det.

Varför Pull Requests?

  • Gruppen ser exakt vilka rader du har ändrat.
  • Man kan kommentera och be om ändringar innan något händer.
  • Ingen kod kommer in i main utan att någon har tittat på den.
  • Mergen görs på GitHub – med en knapp.

En PR skyddar main, så att den alltid fungerar.

Så skapar du en Pull Request

  1. Pusha din branch: git push -u origin feature/meny
  2. Gå till repot på GitHub → Compare & pull request
  3. Skriv en kort titel och vad du har gjort → Create pull request
  4. En kompis granskar och kommenterar.
  5. När alla är nöjda: Merge pull request.

Syns inte knappen? Pull requests → New pull request → välj din branch.

Flödet steg för steg

git switch main
git pull                          # 1. börja från senaste versionen
git switch -c feature/meny        # 2. ny branch för uppgiften
# ... koda, add, commit – ofta ...
git push -u origin feature/meny   # 3. skicka upp branchen
# 4. skapa en Pull Request på GitHub
# 5. någon granskar → Merge
git switch main
git pull                          # 6. hämta den mergade koden
git branch -d feature/meny        # 7. städa

Från din dator till main på GitHub

Du pushar din feature/… och ber på GitHub om att få merga in den i main. Gruppen tittar – sedan Merge.

Reglerna i gruppen

  1. Ingen committar direkt på main.
  2. En feature/…-branch per uppgift.
  3. Håll branchen liten – merga ofta.
  4. Allt kommer in i main via en Pull Request.
  5. Ta bort branchen när den är mergad.
